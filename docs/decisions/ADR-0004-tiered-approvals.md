# ADR-0004 · 分档审批与工作区边界

> 状态：已接受  
> 日期：2026-11-03  
> 关联：[01-architecture.md](../01-architecture.md)、[ADR-0003](./ADR-0003-tool-sources.md)

## 背景

参考场景是本地文件操作。全自动不可接受；全部确认会淹没交互。需要在“可用的 shell”和“默认安全”之间取平衡。用户已明确选择分档审批。

## 决策

- 风险三档：
  - `read`：自动放行；
  - `write`：一次确认；
  - `exec`：两次确认（第二次输入 `run`）。
- 审批用 LangGraph `interrupt()` 实现；CLI 收到后提示，决定后用 `Command({ resume })` 恢复。
- 补充控制：
  - allowlist（工具 + 参数模式）；
  - `--yolo`（仍受硬拒绝列表约束）；
  - 非交互且无脚本策略：write/exec 默认拒绝；
  - 审批超时：拒绝；
  - 文件工具受 workspaceRoot 路径守卫：拒绝 `..`、越界绝对路径、symlink 逃逸；
  - 硬拒绝明显的破坏性命令。
- 同一轮多个风险工具：按模型返回顺序串行审批。

## 后果

**正面**：

- read 流畅，write/exec 有明确安全闸门。
- 审批与 LangGraph 状态机原生集成，可恢复、可审计。
- 路径守卫兜住最常见的越界写入。

**负面/风险**：

- 两次确认增加 exec 的交互成本；需要清晰的 UI。
- interrupt/resume 与 checkpointer、并行 tool call 的边界需要测试。
- 分档审批不是沙箱；同进程插件仍可绕过审批（见 ADR-0007）。
- 提示注入仍可能诱导模型请求危险工具；审批是最后防线。

## 备选方案

- **全部自动**：演示流畅但不可作为壳的默认值。
- **全部确认**：安全但噪音大，read 也会被打断。
- **沙箱目录 + 全自动**：交互最好，但跨平台沙箱实现重，且无法覆盖非文件工具。
- **仅依赖模型自律**：不可接受。

## 复审条件

- 出现可用的跨平台沙箱方案；
- 审批噪音成为主要体验问题；
- exec 的最小权限执行（容器/受限 shell）纳入范围。
