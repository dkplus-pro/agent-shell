# ADR-0007 · 同进程可信插件

> 状态：已接受  
> 日期：2026-11-03  
> 关联：[01-architecture.md](../01-architecture.md)、[ADR-0003](./ADR-0003-tool-sources.md)

## 背景

目录插件需要执行任意 TS/JS 代码。可选的隔离级别：同进程、worker/子进程、声明式（不执行代码）。用户选择 v1 同进程、信任本地插件。

## 决策

- 插件目录 + `plugin.json` manifest：`name`、`version`、`apiVersion`、`entry`、`description`。
- 加载器用 jiti 同进程 `import` 入口；支持 TS/JS。
- 显式启用（`plugins.enabled` + `dirs`）；不自动扫描未配置目录。
- `PLUGIN_API_VERSION = 1`；不匹配拒绝加载。
- 插件工具必须声明 risk；名称加 `plugin__<plugin>__` 前缀；重名拒绝。
- 单个插件加载/执行失败被隔离：记录 `plugin.error`，shell 继续启动。
- v1 不做沙箱、不做热重载、不做依赖解析。

## 后果

**正面**：

- 插件开发简单，可直接复用 TS 类型与本地依赖。
- 加载快，调试方便。
- 与代码工具共享同一套风险/审批/事件。

**负面/风险**：

- **插件与 shell 同权限，可以绕过审批直接读写文件/发网络请求**；审批只约束“工具调用路径”，不是安全边界。
- 只应加载用户信任的本地插件；文档必须显著提示。
- 插件崩溃可能影响进程（通过 try/catch 降低概率，但无法完全隔离）。

## 备选方案

- **worker/子进程隔离**：安全边界清晰，但 IPC、序列化、超时、崩溃恢复成本高，v1 不做。
- **只支持声明式插件**：安全但能力受限，不满足“执行任意 TS/JS 工具”的需求。
- **不做插件**：与用户选择冲突。

## 复审条件

- 出现加载不可信插件的需求；
- 发生插件导致的安全/稳定性事故；
- worker 隔离的工程成本可接受时，另起 ADR 升级。
